# Дашборд + импорты DataLens

## Что делаем
Расширяем текущий `Дашборд` тремя вкладками и добавляем в `Импорт/Экспорт` два новых типа импорта из DataLens. Отдельного раздела `Аналитика` не создаём.

## Вкладки дашборда
- **SEO** — текущие метрики (позиции, TOP-3/10, прогресс мета/текстов). Ничего не ломаем.
- **Бизнес-метрики** — сводка из DataLens: GMV (Categories/Start URL/сумма), товары, селлеры, визиты, пользователи, заказы, конверсия Visit→Order, GMV у непроработанных URL / без мета / без текста.
- **URL-аналитика** — таблица по URL: папка, группа, GMV, товары, селлеры, визиты, заказы, ср. позиции Я/G, %TOP-3/10 Я/G, статус мета/текста, дата последней проработки. Фильтры и сортировки из ТЗ.

Расчёт %TOP-3/10 по URL — только из Topvisor: доля ключей с позицией ≤3 и ≤10, отдельно Я и G, где target/relevant URL совпадает. Если ключей нет — «нет данных». Если URL в нескольких группах — предупреждение.

## Импорт DataLens
В `Import/Export` — два новых блока: `DataLens Categories` и `DataLens Start URL`. Форма: стрим, период (start/end), дата выгрузки, комментарий, файл `.xlsx/.csv`.

Пайплайн импорта (server function):
1. Парсим xlsx/csv, определяем тип отчёта по выбору пользователя, валидируем обязательные колонки.
2. Достаём URL — строка или объект `{'type':'url','url':'...'}` (в т.ч. JSON-подобный текст с одинарными кавычками).
3. Нормализуем URL: без протокола, без `www`, без query, без trailing slash; храним и оригинал, и нормализованный.
4. Матчинг с SEO-URL: exact по нормализованному → по slug → (задел) по Category ID → ручной. Не найдено — `unmatched`. В нескольких группах — `group_conflict`.
5. Сохраняем snapshot импорта и строки метрик в БД.
6. UI показывает: всего строк, сматчено, не сматчено, ошибки/конфликты; кнопка ручной привязки для unmatched.

## Данные (Supabase, новые таблицы)
- `datalens_import` — метаданные снапшота (type, stream, period, uploaded_by/at, file_name, rows_*, status, error_log).
- `datalens_category_metric` — строки Categories (все поля из ТЗ + normalized_url, matched_url_id, matched_group_id, match_status).
- `datalens_start_url_metric` — строки Start URL (все поля из ТЗ + normalized_url, matched_*, match_status).

RLS + GRANT по шаблону проекта. Индексы по `import_id`, `normalized_url`.

## Технические детали
- Импорт: `createServerFn` (`src/lib/datalens.functions.ts` + `.server.ts`), парсинг через уже подключённый xlsx, использование `supabaseAdmin` внутри handler после проверки авторизации.
- Хранение snapshot'ов — БД (не localStorage), т.к. объёмы большие; для дашборда — server fn, отдающие агрегаты по фильтрам (стрим/период/папка/группа), с кэшем через TanStack Query.
- Клиентское состояние текущего периода/стрима — в Zustand (не персистим тяжёлое).
- Расчёт %TOP по URL — на клиенте из уже загруженных Topvisor `queries` (они есть в сторе), чтобы не дублировать запросы.
- Матчинг URL-ов делаем и на импорте (сохраняем `matched_*`), и при отображении (на случай появления новых SEO-URL позже — фоновая переиндексация по кнопке «Переcматчить»).

## Что нужно от вас
Пришлите оба примера `.xlsx` (Categories и Start URL) — зафиксирую точные заголовки колонок и формат ячейки URL перед реализацией парсера.

## Этапы
1. Миграция: 3 таблицы + GRANT/RLS.
2. Server fns: upload+parse, list imports, get aggregates, get url-analytics, rematch.
3. UI импорта: два блока с формой и отчётом матчинга + список unmatched/conflicts с ручной привязкой.
4. Дашборд: табы SEO / Бизнес-метрики / URL-аналитика; фильтры и сортировки; расчёт %TOP из Topvisor.
5. Проверка на реальных файлах, правки парсера под фактические заголовки.
